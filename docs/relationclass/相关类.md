`AbilityEntityEffect` 是 Dragon Survival 提供的一个 **Java 接口**，用于定义“技能作用到实体后，具体执行什么效果”。

例如原版的伤害、点燃、治疗、施加药水效果，都有实现这个接口的类。

它位于：

```java
import by.dragonsurvivalteam.dragonsurvival.registry.dragon.ability.entity_effects.AbilityEntityEffect;
```

### 在技能系统中的位置

一次吐息伤害大致经过：

```text
技能激活
   ↓
AbilityTargeting 选择目标，例如龙息范围内的实体
   ↓
AbilityEntityEffect.apply(...) 对每个目标执行效果
   ↓
扣血、点燃、施加状态等
```

因此，你可以让原版 `DragonBreathTarget` 继续负责范围检测，让自己的 `ExposureDamageEffect` 负责计算递增伤害。

### 两个必须实现的方法

在当前 DS 2.0.71 中，核心接口可以简化为：

```java
public interface AbilityEntityEffect {

    void apply(
            ServerPlayer dragon,
            DragonAbilityInstance ability,
            Entity entity
    );

    MapCodec<? extends AbilityEntityEffect> entityCodec();
}
```

`apply()` 是效果执行入口：

| 参数 | 含义 |
|---|---|
| `dragon` | 施放技能的服务端玩家 |
| `ability` | 当前技能实例，可读取技能等级、ID 等信息 |
| `entity` | 被目标选择器选中的实体，不一定是生物 |

例如，一个固定伤害效果的执行部分：

```java
@Override
public void apply(
        ServerPlayer dragon,
        DragonAbilityInstance ability,
        Entity entity
) {
    if (!(entity instanceof LivingEntity target)) {
        return;
    }

    float damage = 4.0F;

    if (!target.canFreeze()) {
        damage *= 0.5F;
    }

    target.hurt(new DamageSource(damageType, dragon), damage);
}
```

这里的 `damageType` 是你实现类中保存的 `Holder<DamageType>` 配置。

`entityCodec()` 则返回**配置的编解码器**，告诉 DS 如何把 JSON 参数转换成你的 Java 对象：

```java
@Override
public MapCodec<? extends AbilityEntityEffect> entityCodec() {
    return CODEC;
}
```

注册后，DS 遇到：

```json
{
  "effect_type": "dswof:exposure_damage",
  "base_damage": 2.0
}
```

就会根据 `effect_type` 找到你注册的 `CODEC`，再读取 `base_damage` 等字段，构造效果对象。

### 为什么示例使用 `record`？

```java
public record ExposureDamageEffect(...)
        implements AbilityEntityEffect {
}
```

这里：

- `AbilityEntityEffect` 是接口，规定效果必须提供哪些方法。
- `ExposureDamageEffect` 是你编写的实现类。
- `record` 用来方便地保存从 JSON 读取的配置；也可以写成普通 `class`。

**效果对象保存的是配置，不应直接保存某个目标的接触时间。** 同一个效果配置可能被多名玩家、多个目标共同使用。接触时间需要另外按“施法者 + 目标 + 技能”记录，避免互相串数据。

接口还提供 `getDescription()`、`remove()`、`shouldRemoveAutomatically()` 等默认方法。但目标离开龙息范围时，不能直接假定 DS 一定会调用 `remove()`；你的接触计时仍应有超时重置与清理逻辑。
